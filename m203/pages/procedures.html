📦 Les Procédures Stockées

Comprendre les PS simplement : IN, OUT, INOUT

1. Définition

Une procédure stockée (PS) est un ensemble de requêtes SQL enregistré dans la base de données avec un nom, à exécuter en cas de besoin avec CALL.

💡 Image simple : c'est comme une recette de cuisine enregistrée. On ne réécrit pas la recette à chaque fois : on dit juste « fais la recette X avec ces ingrédients » (les paramètres).

Ce qu'elle peut contenir

  • Plusieurs requêtes SQL (SELECT, INSERT, UPDATE, DELETE...).
  • Des instructions conditionnelles : IF, CASE.
  • Des boucles.
  • L'appel d'une autre procédure ou d'une fonction pour découper le code en modules.

2. Pourquoi les utiliser ? (Utilité et avantages)

👉 Quand l'utiliser ? Dès qu'une requête (ou un ensemble de requêtes) doit être répétée régulièrement. Elle est aussi idéale pour déplacer les traitements lourds vers le serveur MySQL.
🌐 Réduire le trafic réseau
Plusieurs requêtes sont regroupées dans une seule procédure. On envoie uniquement le nom et les paramètres au lieu de toutes les requêtes.
🛠️ Facile à maintenir
La logique métier est réutilisable par plusieurs applications ou modules. La base est plus cohérente. Si ça change, on modifie un seul endroit.
🔒 Plus sécurisée
Plus sûre que les requêtes ad hoc. On peut autoriser un utilisateur à exécuter la PS sans lui donner accès aux tables. Elle aide à se protéger contre l'injection SQL.

3. Cas d'utilisation

👨‍💻 Développeurs
Ajouter un développeur ou l'affecter à un projet.
📁 Projets
Afficher les développeurs d'un projet.
💿 Logiciels
Calculer le prix total des logiciels d'un projet.
📊 Rapports
Compter les logiciels ou les projets d'un développeur.

4. Notre base de données

Tous les exemples utilisent la base que nous avons déjà : des développeurs qui réalisent des projets, et chaque projet a des logiciels.

👨‍💻 developpeur
numdev (PK), nomdev, adrdev, emaildev, teldev
📁 projet
numproj (PK), titreproj, datedeb, datefin
💿 logiciel
codlog (PK), nomlog, prixlog, numproj (FK → projet)
🔗 realisation
numproj + numdev (PK composée, FK vers projet et developpeur)
💡 Relations : un projet contient plusieurs logiciels (1,N) · un développeur peut travailler sur plusieurs projets et un projet a plusieurs développeurs (N,N via realisation).

5. Syntaxe (MySQL)

-- Changer le délimiteur pour pouvoir écrire ; dans la procédure
DELIMITER //

CREATE PROCEDURE nom_procedure(
    IN    param1 TYPE,
    OUT   param2 TYPE,
    INOUT param3 TYPE
)
BEGIN
    -- instructions SQL
END //

DELIMITER ;

-- Appel
CALL nom_procedure(...);

-- Suppression
DROP PROCEDURE nom_procedure;

6. Méthodologie simple (5 étapes)

  1. Définir le besoin : que doit faire la procédure ? (ex : afficher les logiciels d'un projet)
  2. Choisir les paramètres : qu'est-ce qui entre ? (IN) Qu'est-ce qui sort ? (OUT)
  3. Écrire la requête SQL à l'intérieur du BEGIN ... END.
  4. Créer la procédure (exécuter le CREATE PROCEDURE).
  5. Appeler et tester avec CALL.

7. Un exemple très simple

Sans paramètre : afficher tous les développeurs.

DELIMITER //
CREATE PROCEDURE afficher_developpeurs()
BEGIN
    SELECT * FROM developpeur;
END //
DELIMITER ;

CALL afficher_developpeurs();

8. Les types de paramètres

TypeSensRôle
INEntrée → PSOn donne une valeur à la PS. Elle la lit seulement (défaut).
OUTPS → SortieLa PS renvoie un résultat dans une variable.
INOUTEntrée ↔ SortieOn donne une valeur, la PS la modifie et la renvoie.

IN Paramètre d'entrée

Exemple 1 : afficher les logiciels d'un projet donné.

DELIMITER //
CREATE PROCEDURE logiciels_du_projet(IN p_numproj INT)
BEGIN
    SELECT codlog, nomlog, prixlog
    FROM logiciel
    WHERE numproj = p_numproj;
END //
DELIMITER ;

CALL logiciels_du_projet(1);

Exemple 2 : ajouter un développeur (plusieurs paramètres IN).

DELIMITER //
CREATE PROCEDURE ajouter_developpeur(
    IN p_nom   VARCHAR(32),
    IN p_adr   VARCHAR(32),
    IN p_email VARCHAR(32),
    IN p_tel   VARCHAR(10)
)
BEGIN
    INSERT INTO developpeur(nomdev, adrdev, emaildev, teldev)
    VALUES (p_nom, p_adr, p_email, p_tel);
END //
DELIMITER ;

CALL ajouter_developpeur('Alaoui Sara', 'Rabat', 'sara@mail.com', '0612345678');

OUT Paramètre de sortie

Calculer le prix total des logiciels d'un projet et récupérer ce total.

DELIMITER //
CREATE PROCEDURE prix_total_projet(
    IN  p_numproj INT,
    OUT p_total   DOUBLE
)
BEGIN
    SELECT IFNULL(SUM(prixlog), 0) INTO p_total
    FROM logiciel
    WHERE numproj = p_numproj;
END //
DELIMITER ;

CALL prix_total_projet(1, @total);
SELECT @total;   -- affiche le résultat

INOUT Paramètre entrée/sortie

Augmenter un prix de logiciel : on envoie le prix, il revient modifié.

DELIMITER //
CREATE PROCEDURE augmenter_prix(
    INOUT p_prix    DOUBLE,
    IN    p_pourcent INT
)
BEGIN
    SET p_prix = p_prix + (p_prix * p_pourcent / 100);
END //
DELIMITER ;

SET @prix = 1000;
CALL augmenter_prix(@prix, 10);
SELECT @prix;   -- 1100
⚠️ Erreur fréquente : avec OUT et INOUT, on ne peut pas passer une valeur directe. La procédure doit écrire le résultat quelque part : il faut donc une variable (@nom).
-- ❌ Faux : 200 est une valeur, pas une variable
CALL augmenter_prix(200, 10);
-- Erreur MySQL : OUT or INOUT argument 1 for routine ... is not a variable

-- ✅ Correct : on met d'abord la valeur dans une variable
SET @prix = 200;
CALL augmenter_prix(@prix, 10);
SELECT @prix;   -- 220

Le paramètre IN n'a pas ce problème : CALL logiciels_du_projet(1); fonctionne avec une valeur directe.

9. Que retourne une procédure ? Deux types de sortie

Attention : OUT ne renvoie qu'une seule valeur (un prix, un total...). Mais une procédure peut aussi renvoyer une liste de lignes (un tableau de résultats) grâce à un simple SELECT.

1️⃣ Une valeur
Avec un paramètre OUT ou INOUT.
Ex : prix total = 4500
2️⃣ Une liste de lignes
Avec un SELECT dans la procédure (pas besoin de OUT).
Ex : les développeurs d'un projet

Exemple : la procédure renvoie plusieurs lignes

DELIMITER //
CREATE PROCEDURE developpeurs_du_projet(IN p_numproj INT)
BEGIN
    -- Ce SELECT renvoie un ensemble de lignes (result set)
    SELECT d.numdev, d.nomdev, d.emaildev
    FROM developpeur d
    JOIN realisation r ON d.numdev = r.numdev
    WHERE r.numproj = p_numproj;
END //
DELIMITER ;

CALL developpeurs_du_projet(1);

Résultat affiché (exemple, selon vos données) :

numdevnomdevemaildev
1Alaoui Sarasara@mail.com
4Bennani Youssefyoussef@mail.com
7Idrissi Amineamine@mail.com
💡 On peut même combiner les deux : afficher la liste des logiciels avec SELECT ET renvoyer leur nombre dans un paramètre OUT.
CREATE PROCEDURE logiciels_et_nombre(IN p_numproj INT, OUT p_nb INT)
BEGIN
    SELECT * FROM logiciel WHERE numproj = p_numproj;                     -- liste de lignes
    SELECT COUNT(*) INTO p_nb FROM logiciel WHERE numproj = p_numproj;    -- une valeur
END

10. À retenir

  • Une PS = un programme SQL enregistré qu'on appelle avec CALL.
  • IN je donne · OUT je reçois · INOUT je donne et je reçois la valeur modifiée.
  • Avec OUT et INOUT, on utilise des variables (@nom) pour récupérer le résultat.
  • Le retour peut être une valeur (OUT / INOUT) ou une liste de lignes (un SELECT dans la procédure).
  • Avantages : réutilisation, rapidité, sécurité, maintenance.

Q1. (Sans paramètre)
    Créer la procédure  afficher_projets()  qui affiche

Q2. (IN)

    Tester avec un prix de 500 et une remise de 20 %
    (attention : passer une variable @prix, pas une valeur).

Q6. (Liste de lignes)
    Créer la procédure  projets_du_developpeur(p_numdev)
    qui affiche le titre et les dates des projets

BONUS.

-- Q1
DELIMITER //
CREATE PROCEDURE afficher_projets()
BEGIN
    SELECT * FROM projet;
END //

-- Q2
CREATE PROCEDURE logiciels_chers(IN p_numproj INT, IN p_prixmin DOUBLE)
BEGIN
    SELECT codlog, nomlog, prixlog
    FROM logiciel
    WHERE numproj = p_numproj AND prixlog > p_prixmin;
END //

-- Q3
CREATE PROCEDURE ajouter_projet(IN p_titre VARCHAR(64), IN p_datedeb DATE, IN p_datefin DATE)
BEGIN
    INSERT INTO projet(titreproj, datedeb, datefin)
    VALUES (p_titre, p_datedeb, p_datefin);
END //

-- Q4
CREATE PROCEDURE nb_developpeurs(IN p_numproj INT, OUT p_nb INT)
BEGIN
    SELECT COUNT(*) INTO p_nb
    FROM realisation
    WHERE numproj = p_numproj;
END //

-- Q5
CREATE PROCEDURE appliquer_remise(INOUT p_prix DOUBLE, IN p_pourcent INT)
BEGIN
    SET p_prix = p_prix - (p_prix * p_pourcent / 100);
END //

-- Q6
CREATE PROCEDURE projets_du_developpeur(IN p_numdev INT)
BEGIN
    SELECT p.titreproj, p.datedeb, p.datefin
    FROM projet p
    JOIN realisation r ON p.numproj = r.numproj
    WHERE r.numdev = p_numdev;
END //

-- BONUS
CREATE PROCEDURE bilan_projet(IN p_numproj INT, OUT p_total DOUBLE)
BEGIN
    SELECT * FROM logiciel WHERE numproj = p_numproj;
    SELECT IFNULL(SUM(prixlog), 0) INTO p_total
    FROM logiciel WHERE numproj = p_numproj;
END //
DELIMITER ;
