⚡ Les déclencheurs (Triggers)

Faire exécuter du code automatiquement par MySQL

Module M203 – Gestion de données

1. Définition

Un déclencheur est une procédure stockée attachée à une table. Elle s'exécute automatiquement quand un événement précis (INSERT, UPDATE ou DELETE) se produit sur cette table. On ne l'appelle jamais soi-même.

Utilisations : valider des données, garder une trace des anciennes/nouvelles valeurs (table d'audit), appliquer des règles métier.

💡 Exemple dans Glogiciels : interdire un salaire négatif pour un développeur, ou archiver une réalisation avant sa suppression.

2. Syntaxe

DELIMITER //
CREATE TRIGGER nom_declencheur
  {BEFORE | AFTER} {INSERT | UPDATE | DELETE}
  ON nom_table
  FOR EACH ROW
BEGIN
  -- corps : instructions à exécuter
END //
DELIMITER ;
ÉlémentRôle
BEFORE | AFTERExécution avant ou après l'opération
INSERT | UPDATE | DELETEL'opération DML qui déclenche
ON nom_tableLa table surveillée
FOR EACH ROWExécuté pour chaque ligne touchée
CorpsLes instructions à exécuter
⚠️ Si le corps contient plusieurs instructions (BEGIN ... END), il faut changer le délimiteur avec DELIMITER. Une seule instruction : BEGIN/END est facultatif.

3. BEFORE ou AFTER ?

BEFOREAFTER
MomentAvant l'opérationAprès l'opération
Usage typiqueContrôler / corriger / refuserJournaliser, mettre à jour une autre table
Peut modifier NEWOuiNon

Cela donne 6 combinaisons possibles : BEFORE/AFTER × INSERT/UPDATE/DELETE.

4. Les pseudo-lignes OLD et NEW

  • OLD : la ligne avant modification (ancienne valeur).
  • NEW : la ligne après modification (nouvelle valeur).
TriggerOLDNEW
INSERT❌✔
UPDATE✔✔
DELETE✔❌
✅ Logique : à l'insertion il n'y a pas d'ancienne ligne ; à la suppression il n'y a pas de nouvelle ligne.

5. Exemples sur la base Glogiciels

ℹ️ Les noms de colonnes sont à adapter à votre schéma : ici Developpeur(id_dev, nom, prenom, salaire) et Realisation(id_dev, id_projet, ...).

BEFORE INSERT : refuser un salaire invalide

DELIMITER //
CREATE TRIGGER tr_dev_salaire_insert
BEFORE INSERT ON Developpeur
FOR EACH ROW
BEGIN
  IF NEW.salaire < 0 THEN
    SIGNAL SQLSTATE '45000'
    SET MESSAGE_TEXT = 'Le salaire ne peut pas être négatif.';
  END IF;
END //
DELIMITER ;

-- Test : provoque l'erreur
INSERT INTO Developpeur (nom, prenom, salaire) VALUES ('Slami', 'Saida', -500);

SIGNAL déclenche une erreur : l'insertion est annulée.

BEFORE UPDATE : même contrôle à la modification

DELIMITER //
CREATE TRIGGER tr_dev_salaire_update
BEFORE UPDATE ON Developpeur
FOR EACH ROW
BEGIN
  IF NEW.salaire < 0 THEN
    SIGNAL SQLSTATE '45000'
    SET MESSAGE_TEXT = 'Le salaire ne peut pas être négatif.';
  END IF;
END //
DELIMITER ;

AFTER UPDATE : journaliser les changements de salaire

CREATE TABLE Audit_Salaire (
  id INT AUTO_INCREMENT PRIMARY KEY,
  id_dev INT,
  ancien_salaire DECIMAL(10,2),
  nouveau_salaire DECIMAL(10,2),
  date_modif DATETIME DEFAULT CURRENT_TIMESTAMP
);

DELIMITER //
CREATE TRIGGER tr_audit_salaire
AFTER UPDATE ON Developpeur
FOR EACH ROW
BEGIN
  IF OLD.salaire <> NEW.salaire THEN
    INSERT INTO Audit_Salaire (id_dev, ancien_salaire, nouveau_salaire)
    VALUES (OLD.id_dev, OLD.salaire, NEW.salaire);
  END IF;
END //
DELIMITER ;

-- Test
UPDATE Developpeur SET salaire = 9000 WHERE id_dev = 1;
SELECT * FROM Audit_Salaire;

BEFORE DELETE : archiver avant de supprimer

CREATE TABLE Archive_Developpeur LIKE Developpeur;

DELIMITER //
CREATE TRIGGER tr_archive_dev
BEFORE DELETE ON Developpeur
FOR EACH ROW
BEGIN
  INSERT INTO Archive_Developpeur
  VALUES (OLD.id_dev, OLD.nom, OLD.prenom, OLD.salaire);
END //
DELIMITER ;

AFTER INSERT : mettre à jour une valeur calculée

CREATE TABLE Stat_Projet (id_projet INT PRIMARY KEY, nb_dev INT DEFAULT 0);

CREATE TRIGGER tr_nb_dev_ajout
AFTER INSERT ON Realisation
FOR EACH ROW
  UPDATE Stat_Projet SET nb_dev = nb_dev + 1
  WHERE id_projet = NEW.id_projet;

AFTER DELETE : l'inverse

CREATE TRIGGER tr_nb_dev_retrait
AFTER DELETE ON Realisation
FOR EACH ROW
  UPDATE Stat_Projet SET nb_dev = nb_dev - 1
  WHERE id_projet = OLD.id_projet;
✅ Une seule instruction dans le corps : pas besoin de BEGIN ... END ni de DELIMITER.

6. Avantages

  • Renforcent l'intégrité des données.
  • Détectent les erreurs au plus tôt.
  • Automatisent des tâches (plus besoin de les planifier).
  • Permettent l'audit : historique des changements, prévention des opérations invalides.

7. Restrictions

  • Un trigger ne retourne aucune valeur.
  • Pas de COMMIT / ROLLBACK / START TRANSACTION dans le corps.
  • Impossible de modifier, dans le trigger, la table qui l'a déclenché (erreur 1442).
  • Pas de trigger sur une table temporaire ni sur une vue.
  • Selon le moteur (InnoDB, MyISAM…), les résultats peuvent varier : InnoDB annule aussi les effets du trigger si l'opération échoue.
  • Selon le support de cours : un seul trigger par événement et par moment (ex. un seul BEFORE UPDATE par table), mais il peut contenir plusieurs instructions.

8. Gérer les déclencheurs

-- Lister les triggers de la base
SHOW TRIGGERS;

-- Supprimer un trigger
DROP TRIGGER IF EXISTS Glogiciels.tr_audit_salaire;

-- Modifier un trigger : pas de ALTER, on supprime puis on recrée
DROP TRIGGER IF EXISTS tr_audit_salaire;
-- puis CREATE TRIGGER ... à nouveau
⚠️ Si on supprime une table, MySQL supprime automatiquement tous ses triggers.

9. À retenir

  • Trigger = code automatique lié à une table et à un événement.
  • BEFORE pour contrôler, AFTER pour journaliser / répercuter.
  • NEW = nouvelle ligne, OLD = ancienne ligne.
  • SIGNAL pour refuser une opération.
  • SHOW TRIGGERS pour lister, DROP TRIGGER pour supprimer.
