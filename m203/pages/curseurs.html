Les curseurs

Module M203 – Traiter un résultat de SELECT ligne par ligne

1. Définition

Un curseur est une zone mémoire créée côté serveur qui garde le résultat d'un SELECT et permet de traiter les lignes une par une.

Pendant qu'il est ouvert, le curseur « pointe » toujours sur une ligne courante. À chaque lecture, il avance à la ligne suivante.

Image à retenir Un SELECT renvoie un tableau entier. Le curseur, c'est un doigt qui descend le tableau ligne par ligne pour lire chaque ligne avant de passer à la suivante.

Un même sous-programme (procédure, fonction) peut utiliser plusieurs curseurs en même temps.

2. Pourquoi utiliser un curseur ?

Une requête SQL travaille sur un ensemble de lignes. Mais parfois il faut appliquer une logique différente à chaque ligne (tests, calculs, insertions ailleurs). C'est là que le curseur sert.

  • Parcourir les lignes d'un SELECT et agir sur chacune
  • Construire un résultat à partir de plusieurs lignes (liste, total, rapport)
  • Copier ou transformer des lignes vers une autre table selon des conditions
Quand utiliser un curseur ? Si un simple UPDATE, INSERT ... SELECT ou SUM() suffit, utilisez-le : c'est plus simple et plus rapide. Le curseur est justifié dans deux cas :
  • le traitement d'une ligne dépend de ce qui s'est passé sur les lignes précédentes (total cumulé, budget restant, compteur d'état) ;
  • il faut exécuter une procédure ou une série d'instructions pour chaque ligne (un CALL ne peut pas être placé dans un SELECT).

3. Les 3 propriétés d'un curseur MySQL

Read-only

Lecture seule : on ne modifie pas la base à travers le curseur (sauf avec la clause FOR UPDATE).

Non-scrollable

Non navigable : on parcourt du début à la fin, sans jamais revenir à la ligne précédente.

Asensitive

Insensible : le curseur travaille sur une copie temporaire. Une mise à jour faite après l'ouverture n'y apparaît pas.

4. Les étapes d'utilisation

  1. DECLARE : on déclare le curseur avec son SELECT.
  2. OPEN : on ouvre le curseur, le SELECT s'exécute et le résultat est prêt.
  3. FETCH : on lit la ligne courante dans des variables, puis le curseur avance. On répète dans une boucle.
  4. CLOSE : on ferme le curseur pour libérer la mémoire.

5. Syntaxe

DECLARE nom_curseur CURSOR FOR instruction_SELECT;

OPEN nom_curseur;

FETCH nom_curseur INTO variable1, variable2, ...;

CLOSE nom_curseur;

Le nombre de variables du FETCH ... INTO doit être égal au nombre de colonnes du SELECT, dans le même ordre.

Ordre de déclaration dans le bloc BEGIN ... END

MySQL impose cet ordre. S'il n'est pas respecté, la procédure ne se crée pas :

  1. Les variables (DECLARE x INT;)
  2. Les curseurs (DECLARE c CURSOR FOR ...)
  3. Les handlers (DECLARE ... HANDLER ...)

6. Le problème de la fin des lignes

Quand le curseur n'a plus de ligne à lire, le FETCH déclenche l'erreur NOT FOUND. Sans précaution, la procédure s'arrête avec une erreur.

On prévoit donc un handler qui lève un indicateur de fin, et on sort de la boucle quand il vaut 1 :

DECLARE fini INT DEFAULT 0;
DECLARE CONTINUE HANDLER FOR NOT FOUND SET fini = 1;
Schéma de la boucle OPEN → boucle : FETCH → si fini = 1 alors LEAVE → sinon traiter la ligne → recommencer → CLOSE

7. Exemple 1 – Acheter des logiciels avec un budget

Problème : on a un budget. On regarde les logiciels un par un. Si le prix est inférieur ou égal au budget qui reste, on l'achète (le budget diminue). Sinon on passe au suivant.

Résultat voulu : le nombre de logiciels achetés et le budget restant.

Pourquoi un curseur ? Le budget restant change à chaque achat. Pour chaque ligne, il faut connaître ce qui s'est passé sur les lignes d'avant. Un SELECT ne peut pas faire ça. 
DELIMITER $$
CREATE PROCEDURE Acheter(IN budget DECIMAL(10,2),
                       OUT nb INT,
                       OUT reste DECIMAL(10,2))
BEGIN
  -- variables
  DECLARE v_prix DECIMAL(10,2);
  DECLARE fini INT DEFAULT 0;

  -- curseur : le prix de chaque logiciel
  DECLARE c_log CURSOR FOR SELECT prixlog FROM logiciel;

  -- fin des lignes
  DECLARE CONTINUE HANDLER FOR NOT FOUND SET fini = 1;

  SET nb = 0;
  SET reste = budget;

  OPEN c_log;

  boucle: LOOP
    FETCH c_log INTO v_prix;
    IF fini = 1 THEN LEAVE boucle; END IF;

    -- si le logiciel rentre dans le budget restant, on l'achète
    IF v_prix <= reste THEN
      SET reste = reste - v_prix;
      SET nb = nb + 1;
    END IF;
  END LOOP;

  CLOSE c_log;
END$$
DELIMITER ;

Appel :

CALL Acheter(10000, @nb, @reste);
SELECT @nb AS logiciels_achetes, @reste AS budget_restant;

8. Exemple 2 – Appeler une procédure pour chaque ligne

Problème : pour chaque développeur d'un projet, on veut enregistrer une ligne dans une table journal en appelant la procédure AjouterJournal.

Pourquoi un curseur ? On ne peut pas mettre un CALL dans un SELECT. Pour exécuter une procédure sur chaque ligne, on parcourt les lignes avec un curseur.

Préparation (table et procédure appelée) :

CREATE TABLE journal (
  numdev INT,
  message VARCHAR(100)
);

DELIMITER $$
CREATE PROCEDURE AjouterJournal(IN p_numdev INT, IN p_msg VARCHAR(100))
BEGIN
  INSERT INTO journal VALUES (p_numdev, p_msg);
END$$
DELIMITER ;

Procédure avec curseur :

DELIMITER $$
CREATE PROCEDURE NotifierEquipe(IN p_numproj INT)
BEGIN
  DECLARE v_num INT;
  DECLARE v_nom VARCHAR(50);
  DECLARE fini INT DEFAULT 0;

  -- curseur : les développeurs du projet
  DECLARE c_dev CURSOR FOR
    SELECT d.numdev, d.nomdev
    FROM developpeur d
    JOIN realisation r ON r.numdev = d.numdev
    WHERE r.numproj = p_numproj;

  DECLARE CONTINUE HANDLER FOR NOT FOUND SET fini = 1;

  OPEN c_dev;
  FETCH c_dev INTO v_num, v_nom;      -- 1re lecture

  WHILE fini = 0 DO
    CALL AjouterJournal(v_num, CONCAT('Notifié : ', v_nom));
    FETCH c_dev INTO v_num, v_nom;    -- ligne suivante
  END WHILE;

  CLOSE c_dev;
END$$
DELIMITER ;

CALL NotifierEquipe(1);
SELECT * FROM journal;
Remarque Avec WHILE, on fait un FETCH avant la boucle, puis un FETCH à la fin de chaque tour. Avec LOOP, un seul FETCH au début suffit.

9. Erreurs fréquentes

Nombre de variables ≠ nombre de colonnesErreur au FETCHUne variable par colonne, même ordre

10. Méthodologie en 6 points

  1. Écrire d'abord le SELECT et le tester seul.
  2. Déclarer une variable par colonne, puis le curseur, puis le handler NOT FOUND.
  3. OPEN le curseur.
  4. Dans une boucle : FETCH, tester fini, traiter la ligne.
  5. CLOSE le curseur.
  6. Vérifier qu'une requête simple (UPDATE, SUM...) ne ferait pas le même travail.

Résumé

À retenir Un curseur parcourt un résultat de SELECT ligne par ligne : DECLARE → OPEN → FETCH (en boucle) → CLOSE. Il est en lecture seule, non navigable et insensible aux modifications faites après l'ouverture. Le handler NOT FOUND permet de détecter la fin des lignes.
