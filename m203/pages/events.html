Événements planifiés (Events)

MySQL – Module M203 : Gestion de données

1Définition

Un événement MySQL est une tâche qui s'exécute automatiquement selon un calendrier défini à l'avance. On parle aussi d'événement planifié.

MySQL utilise un thread spécial, le planificateur d'événements (event scheduler), pour exécuter tous les événements.

💡 Image simple : un événement, c'est comme une alarme sur le téléphone : on la programme une fois, et elle se déclenche toute seule à l'heure voulue.

2Pourquoi les utiliser ?

  • Automatiser des tâches répétitives, sans intervention humaine.
  • Ne plus dépendre d'un programme externe (cron, script...) : tout reste dans MySQL.
  • Gagner du temps et éviter les oublis.

Cas d'utilisation

  • Supprimer chaque nuit les anciennes données (logs, sessions expirées).
  • Générer chaque jour ou chaque mois des statistiques et rapports.
  • Faire des sauvegardes ou archiver des tables à intervalle régulier.
  • Mettre à jour automatiquement un état (ex. : abonnement expiré).

3Activer le planificateur

Les événements ne s'exécutent que si le planificateur est activé. On vérifie son état :

SHOW VARIABLES LIKE 'event_scheduler';

Valeur ON = actif, OFF = arrêté. Pour l'activer :

SET GLOBAL event_scheduler = ON;

On peut aussi voir le thread du planificateur dans la liste des processus :

SHOW PROCESSLIST;

On y trouve une ligne dont l'utilisateur est event_scheduler et l'état Waiting on empty queue (ou similaire).

4Syntaxe

CREATE EVENT [IF NOT EXISTS] nom_evenement
ON SCHEDULE planification
[ENABLE | DISABLE]
DO
  instruction;

La planification peut prendre deux formes :

TypeSyntaxeSignification
Une seule foisAT date_heureExécuté une fois à ce moment précis
RépétitifEVERY n unité [STARTS ...] [ENDS ...]Exécuté toutes les n minutes, heures, jours...

Unités possibles : SECOND, MINUTE, HOUR, DAY, WEEK, MONTH, YEAR.

Si l'action contient plusieurs instructions, on utilise un bloc BEGIN ... END (comme dans une procédure stockée, avec DELIMITER).

5Exemples

On prépare d'abord une table pour recevoir les résultats :

CREATE TABLE messages (
  id INT AUTO_INCREMENT PRIMARY KEY,
  message VARCHAR(255),
  created_at DATETIME
);

Exemple 1 : événement exécuté une seule fois

CREATE EVENT test_event_01
ON SCHEDULE AT CURRENT_TIMESTAMP + INTERVAL 1 MINUTE
DO
  INSERT INTO messages (message, created_at)
  VALUES ('Test MySQL one-time Event', NOW());

Dans 1 minute, une ligne sera ajoutée dans messages. Ensuite, l'événement est supprimé automatiquement (comportement par défaut).

Exemple 2 : événement récurrent

CREATE EVENT test_event_03
ON SCHEDULE EVERY 1 MINUTE
  STARTS CURRENT_TIMESTAMP
  ENDS CURRENT_TIMESTAMP + INTERVAL 1 HOUR
DO
  INSERT INTO messages (message, created_at)
  VALUES ('Test MySQL recurring Event', NOW());

Explication :

  • EVERY 1 MINUTE : se répète toutes les minutes.
  • STARTS CURRENT_TIMESTAMP : démarre maintenant.
  • ENDS CURRENT_TIMESTAMP + INTERVAL 1 HOUR : s'arrête après 1 heure (donc environ 60 lignes insérées).
  • DO ... : l'action à réaliser à chaque déclenchement.

Pour vérifier le résultat :

SELECT * FROM messages;
⚠️ Attention aux erreurs fréquentes : ne pas oublier la parenthèse fermante après created_at et utiliser des apostrophes droites '...' (et non des guillemets typographiques copiés depuis Word ou PowerPoint).

6Gérer les événements

-- Afficher tous les événements de la base
SHOW EVENTS;

-- Désactiver un événement (sans le supprimer)
ALTER EVENT test_event_03 DISABLE;

-- Le réactiver
ALTER EVENT test_event_03 ENABLE;

-- Supprimer un événement
DROP EVENT IF EXISTS test_event_03;
✅ Après le test, pensez à supprimer l'événement récurrent, sinon il continue à remplir la table jusqu'à sa date de fin.

7Cas pratiques sur la base Glogiciels

Voici 4 situations réelles pour notre base : developpeur, projet, logiciel, realisation.

💡 Pour tester en classe : remplacez la planification par EVERY 1 MINUTE afin de voir le résultat tout de suite. En situation réelle, on utilise EVERY 1 DAY.

Cas 1 : archiver automatiquement les projets terminés

Besoin : chaque nuit, copier dans une table d'archive les projets dont la date de fin est dépassée.

CREATE TABLE projet_archive LIKE projet;

CREATE EVENT ev_archiver_projets
ON SCHEDULE EVERY 1 DAY
  STARTS CURRENT_DATE + INTERVAL 1 DAY + INTERVAL 2 HOUR
DO
  INSERT INTO projet_archive
  SELECT * FROM projet
  WHERE datefin < CURDATE()
    AND numproj NOT IN (SELECT numproj FROM projet_archive);

Chaque nuit à 2h, les projets terminés sont copiés une seule fois (le NOT IN évite les doublons).

Cas 2 : statistiques quotidiennes sur les logiciels

Besoin : garder chaque jour une trace du nombre de logiciels et de leur prix moyen.

CREATE TABLE stat_logiciels (
  id INT AUTO_INCREMENT PRIMARY KEY,
  date_stat DATE,
  nb_logiciels INT,
  prix_moyen DECIMAL(10,2)
);

CREATE EVENT ev_stat_logiciels
ON SCHEDULE EVERY 1 DAY
  STARTS CURRENT_DATE + INTERVAL 1 DAY
DO
  INSERT INTO stat_logiciels (date_stat, nb_logiciels, prix_moyen)
  SELECT CURDATE(), COUNT(*), AVG(prixlog)
  FROM logiciel;

Chaque nuit à minuit, une nouvelle ligne est ajoutée : on obtient l'évolution des logiciels jour après jour.

Cas 3 : rappel des projets qui se terminent bientôt

Besoin : chaque matin, préparer la liste des projets dont la date de fin tombe dans les 7 prochains jours.

Ici l'action contient deux instructions : on utilise BEGIN ... END avec DELIMITER.

CREATE TABLE rappel_echeances (
  numproj INT,
  titreproj VARCHAR(100),
  datefin DATE
);

DELIMITER $$
CREATE EVENT ev_rappel_echeances
ON SCHEDULE EVERY 1 DAY
  STARTS CURRENT_DATE + INTERVAL 1 DAY + INTERVAL 8 HOUR
DO
BEGIN
  -- 1) vider l'ancienne liste
  DELETE FROM rappel_echeances;
  -- 2) la remplir avec les projets proches de leur fin
  INSERT INTO rappel_echeances (numproj, titreproj, datefin)
  SELECT numproj, titreproj, datefin
  FROM projet
  WHERE datefin BETWEEN CURDATE() AND CURDATE() + INTERVAL 7 DAY;
END$$
DELIMITER ;

Chaque matin à 8h, il suffit de faire SELECT * FROM rappel_echeances; pour voir les projets urgents.

Cas 4 : nettoyer automatiquement une table de journal

Besoin : supprimer chaque jour les lignes de la table messages (créée plus haut) qui ont plus de 7 jours, pour qu'elle ne grossisse pas indéfiniment.

CREATE EVENT ev_nettoyer_messages
ON SCHEDULE EVERY 1 DAY
  STARTS CURRENT_DATE + INTERVAL 1 DAY + INTERVAL 3 HOUR
DO
  DELETE FROM messages
  WHERE created_at < NOW() - INTERVAL 7 DAY;

8Méthodologie simple

  1. Vérifier que le planificateur est activé (event_scheduler = ON).
  2. Écrire et tester d'abord l'instruction SQL seule.
  3. Choisir la planification : une fois (AT) ou répétitive (EVERY).
  4. Créer l'événement avec CREATE EVENT.
  5. Vérifier avec SHOW EVENTS puis contrôler le résultat dans la table.
  6. Désactiver ou supprimer l'événement quand il n'est plus utile.

9Mini TP (base Glogiciels)

Créer une table de suivi puis un événement qui y enregistre, toutes les minutes pendant 10 minutes, le nombre de projets :

CREATE TABLE suivi_projets (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nb_projets INT,
  date_suivi DATETIME
);
  1. Créer l'événement ev_suivi_projets (toutes les minutes, pendant 10 minutes) qui insère COUNT(*) de la table projet dans suivi_projets.
  2. Afficher le contenu de suivi_projets après quelques minutes.
  3. Désactiver l'événement, puis le supprimer.
