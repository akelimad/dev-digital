Les structures de contrôle en MySQL

IF · CASE · WHILE · REPEAT · LOOP — M203 Gestion de données

1. Définition

Une structure de contrôle permet de décider quelles instructions exécuter (condition) ou de répéter des instructions (boucle), au lieu de les exécuter simplement l'une après l'autre.

  • Structures conditionnelles : IF, CASE
  • Structures répétitives (boucles) : WHILE, REPEAT, LOOP
Les structures de contrôle s'utilisent à l'intérieur d'un programme stocké (procédure, fonction, trigger, événement), entre BEGIN et END. On ne peut pas écrire un IF ... END IF directement dans une requête seule.

2. Pourquoi les utiliser ? (utilité)

  • Faire des choix selon les données (prix, dates, valeurs saisies).
  • Répéter un calcul sans recopier le code.
  • Rendre une procédure ou une fonction intelligente : elle réagit au lieu d'exécuter toujours la même chose.
  • Contrôler les valeurs avant de modifier la base.

3. Cas d'utilisation

BesoinStructure
Classer un logiciel (économique / moyen / cher)IF ... ELSEIF ... ELSE

Les exemples de IF et CASE utilisent la base Glogiciels : developpeur, projet, logiciel, realisation. Les exemples des boucles sont dynamiques : un nombre est passé en paramètre.

4. Syntaxe et exemples

4.1 IF — ELSEIF — ELSE

IF condition1 THEN
    instructions;
ELSEIF condition2 THEN
    instructions;
ELSE
    instructions;
END IF;

Exemple : classer un logiciel selon son prix.

DELIMITER //
CREATE PROCEDURE categorie_logiciel(IN p_codlog INT)
BEGIN
    DECLARE v_prix DECIMAL(10,2);

    SELECT prixlog INTO v_prix
    FROM logiciel
    WHERE codlog = p_codlog;

    IF v_prix >= 1000 THEN
        SELECT 'Logiciel cher' AS categorie;
    ELSEIF v_prix >= 300 THEN
        SELECT 'Logiciel moyen' AS categorie;
    ELSE
        SELECT 'Logiciel économique' AS categorie;
    END IF;
END //
DELIMITER ;

CALL categorie_logiciel(1);
Attention à l'écriture : ELSEIF en un seul mot, et chaque IF se termine par END IF;.

4.2 CASE (2 formes)

CASE existe sous deux formes : avec paramètre (on compare une valeur) et sans paramètre (on écrit des conditions complètes).

Forme 1 : CASE avec paramètre (on compare une expression à des valeurs, uniquement par égalité =)

CASE expression
    WHEN valeur1 THEN instructions;
    WHEN valeur2 THEN instructions;
    ELSE instructions;
END CASE;

Exemple : afficher le trimestre de début d'un projet.

DELIMITER //
CREATE PROCEDURE trimestre_projet(IN p_numproj INT)
BEGIN
    DECLARE v_deb DATE;

    SELECT datedeb INTO v_deb
    FROM projet
    WHERE numproj = p_numproj;

    CASE QUARTER(v_deb)
        WHEN 1 THEN SELECT 'Trimestre 1 (janv. - mars)' AS trimestre;
        WHEN 2 THEN SELECT 'Trimestre 2 (avr. - juin)'  AS trimestre;
        WHEN 3 THEN SELECT 'Trimestre 3 (juil. - sept.)' AS trimestre;
        WHEN 4 THEN SELECT 'Trimestre 4 (oct. - déc.)'  AS trimestre;
        ELSE SELECT 'Date de début inconnue' AS trimestre;
    END CASE;
END //
DELIMITER ;
Ici QUARTER(v_deb) est évalué une seule fois, puis comparé à 1, 2, 3, 4.

Forme 2 : CASE sans paramètre (chaque WHEN contient sa propre condition : <, >=, IS NULL, AND...)

CASE
    WHEN condition1 THEN instructions;
    WHEN condition2 THEN instructions;
    ELSE instructions;
END CASE;

Exemple : donner l'état d'un projet selon sa date de fin.

DELIMITER //
CREATE PROCEDURE statut_projet(IN p_numproj INT)
BEGIN
    DECLARE v_fin DATE;

    SELECT datefin INTO v_fin
    FROM projet
    WHERE numproj = p_numproj;

    CASE
        WHEN v_fin IS NULL THEN
            SELECT 'Date de fin non définie' AS statut;
        WHEN v_fin < CURDATE() THEN
            SELECT 'Terminé' AS statut;
        ELSE
            SELECT 'En cours' AS statut;
    END CASE;
END //
DELIMITER ;

CALL statut_projet(1);
CASE avec paramètreCASE sans paramètre
SyntaxeCASE expr WHEN valeurCASE WHEN condition
Comparaisonégalité seulement (=)toute condition (<, >=, AND, IS NULL...)
Quand l'utiliservaleurs précises (1, 2, 3 ou 'A', 'B')intervalles et conditions variées
Piège avec NULL : dans la forme avec paramètre, WHEN NULL ne correspond jamais (car NULL = NULL n'est pas vrai). Pour tester NULL, utilisez la forme sans paramètre avec IS NULL.
Dans une procédure, si aucune branche WHEN ne correspond et qu'il n'y a pas de ELSE, MySQL génère une erreur. Prévoyez toujours un ELSE.

4.3 WHILE (tester d'abord)

WHILE condition DO
    instructions;
END WHILE;

La condition est testée avant chaque tour : si elle est fausse dès le départ, la boucle ne s'exécute jamais.

Pourquoi choisir WHILE ? C'est le choix par défaut : on connaît la condition avant de commencer, et il est normal que la boucle ne s'exécute pas du tout (par exemple n = 0). Si vous n'avez pas de raison particulière d'utiliser REPEAT ou LOOP, prenez WHILE.
Les exemples des boucles sont dynamiques : la valeur est passée en paramètre (IN p_n) et on appelle la procédure avec le nombre voulu. Les compteurs sont des variables locales (DECLARE) qui disparaissent à la fin de la procédure.

Exemple : afficher les nombres de 1 à n.

DELIMITER //
CREATE PROCEDURE while_1_a_n(IN p_n INT)
BEGIN
    DECLARE v_counter  INT DEFAULT 1;
    DECLARE v_resultat VARCHAR(255) DEFAULT '';

    WHILE v_counter <= p_n DO
        SET v_resultat = CONCAT(v_resultat, v_counter, '\n');
        SET v_counter  = v_counter + 1;
    END WHILE;

    SELECT v_resultat AS nombres;
END //
DELIMITER ;

CALL while_1_a_n(5);    -- essayez aussi 3, 10...

Résultat de CALL while_1_a_n(5) :

1
2
3
4
5
Boucle infinie : la condition doit pouvoir devenir fausse. Si on oublie SET v_counter = v_counter + 1;, le compteur ne change jamais et la boucle ne s'arrête pas.
Erreur 2014 « Commands out of sync » : elle apparaît quand une procédure renvoie plusieurs résultats (un SELECT dans chaque tour de boucle) et que le client ne les lit pas tous avant la commande suivante. Pour l'éviter, on accumule les valeurs dans une variable (CONCAT) et on fait un seul SELECT après la boucle, comme dans cet exemple.
'\n' est un retour à la ligne : le résultat tient dans une seule cellule mais sur plusieurs lignes. Le client en ligne de commande mysql l'affiche tel quel ; dans Workbench ou phpMyAdmin, ouvrez la valeur de la cellule (visionneuse) pour voir une ligne par nombre.

4.4 REPEAT (exécuter d'abord, tester ensuite)

REPEAT
    instructions;
UNTIL condition
END REPEAT;

La boucle s'arrête quand la condition devient vraie (le contraire de WHILE). Elle s'exécute au moins une fois, car la condition est testée à la fin.

Exemple : lancer un dé jusqu'à obtenir 6 et compter le nombre de lancers.

DELIMITER //
CREATE PROCEDURE lancer_de()
BEGIN
    DECLARE v_de     INT;               -- pas de valeur de départ nécessaire
    DECLARE v_essais INT DEFAULT 0;

    REPEAT
        SET v_de     = FLOOR(1 + RAND() * 6);
        SET v_essais = v_essais + 1;
    UNTIL v_de = 6
    END REPEAT;

    SELECT v_essais AS nombre_lancers;
END //
DELIMITER ;

CALL lancer_de();

Résultat (varie à chaque appel) :

4
Pourquoi REPEAT et pas WHILE ? Ici, la condition d'arrêt (v_de = 6) dépend d'une valeur calculée dans la boucle : avant le premier lancer, v_de n'existe pas encore. Avec WHILE, il faudrait inventer une valeur artificielle au départ (SET v_de = 0;) juste pour entrer dans la boucle, ou recopier le lancer avant la boucle. Avec REPEAT, on agit d'abord, on vérifie ensuite, ce qui correspond exactement au problème.
Autres cas typiques : réessayer une opération jusqu'à ce qu'elle réussisse, ou générer un code aléatoire et recommencer tant qu'il existe déjà dans la table.

4.5 LOOP et LEAVE

etiquette: LOOP
    instructions;
    IF condition_arret THEN
        LEAVE etiquette;     -- sortir de la boucle
    END IF;
END LOOP etiquette;
  • LOOP ne s'arrête jamais toute seule : il faut obligatoirement un LEAVE.
  • LEAVE etiquette : sort de la boucle.
  • ITERATE etiquette : passe directement à l'itération suivante (comme continue).
L'étiquette est-elle obligatoire ? Pour la syntaxe de LOOP elle est facultative, mais LEAVE et ITERATE ont besoin d'une étiquette pour savoir quelle boucle quitter. Comme un LOOP sans LEAVE ne s'arrête jamais, en pratique l'étiquette est obligatoire (ex. boucle:). Si on écrit l'étiquette de fin (END LOOP boucle;), elle doit être identique à celle du début. Les boucles WHILE et REPEAT peuvent aussi avoir une étiquette, utile seulement si on y utilise LEAVE ou ITERATE.

Exemple : remplir la table cities avec n lignes : (i, 'city i').

CREATE TABLE cities (
    id   INT PRIMARY KEY,
    name VARCHAR(50)
);

DELIMITER //
CREATE PROCEDURE remplir_cities(IN p_n INT)
BEGIN
    DECLARE v_i INT DEFAULT 1;

    boucle: LOOP
        IF v_i > p_n THEN
            LEAVE boucle;
        END IF;

        INSERT INTO cities (id, name)
        VALUES (v_i, CONCAT('city ', v_i));

        SET v_i = v_i + 1;
    END LOOP boucle;
END //
DELIMITER ;

CALL remplir_cities(5);    -- essayez aussi 3, 10...
SELECT * FROM cities;

Résultat de SELECT * FROM cities :

id | name
---+--------
 1 | city 1
 2 | city 2
 3 | city 3
 4 | city 4
 5 | city 5
Pour relancer la procédure, videz d'abord la table avec TRUNCATE TABLE cities;, sinon MySQL signale une erreur de clé primaire dupliquée.
Pourquoi LOOP et pas WHILE ou REPEAT ? Cet exemple pourrait aussi s'écrire avec WHILE. LOOP devient préférable quand WHILE (test au début) et REPEAT (test à la fin) ne suffisent plus, car LOOP permet de sortir n'importe où dans le corps :
  • Sortie au milieu : on fait une partie du travail, puis on décide de continuer ou de sortir.
  • Plusieurs conditions de sortie : plusieurs LEAVE à des endroits différents, sans une longue condition AND / OR.
  • ITERATE : avec LOOP, on incrémente le compteur en haut du tour, puis on peut sauter un tour sans risque. Dans un WHILE, il faudrait refaire l'incrémentation avant chaque ITERATE, sinon la boucle devient infinie.
Contrepartie : LOOP est plus long à écrire et il ne faut jamais oublier le LEAVE.

4.6 Bonus : IF() et CASE dans une requête SELECT

Dans un SELECT (hors programme stocké), on utilise la fonction IF() et l'expression CASE ... END :

SELECT nomlog, prixlog,
       IF(prixlog >= 1000, 'Cher', 'Abordable') AS niveau,
       CASE
           WHEN prixlog >= 1000 THEN 'Cher'
           WHEN prixlog >= 300  THEN 'Moyen'
           ELSE 'Économique'
       END AS categorie
FROM logiciel;

-- CASE avec paramètre dans un SELECT
SELECT titreproj,
       CASE QUARTER(datedeb)
           WHEN 1 THEN 'T1'
           WHEN 2 THEN 'T2'
           WHEN 3 THEN 'T3'
           ELSE 'T4'
       END AS trimestre
FROM projet;
Différence : dans une requête, CASE ... END (sans CASE final) ; dans une procédure, CASE ... END CASE;.

5. Choisir la bonne structure

Tout programme avec REPEAT ou LOOP peut s'écrire avec WHILE : le choix est une question de clarté, pas de puissance.

StructureTest de la conditionOn la choisit quand...Pourquoi pas les autres ?
WHILEAvant chaque tourla condition est connue au départ et 0 tour est possibleC'est le choix par défaut, le plus simple
REPEATAprès chaque touril faut agir au moins une fois, ou la condition dépend d'une valeur calculée dans la boucleWHILE obligerait à une valeur de départ artificielle ou à recopier le code avant la boucle
LOOPOù l'on veut (LEAVE)on sort au milieu du corps, avec plusieurs sorties ou avec ITERATEWHILE et REPEAT ne testent qu'au début ou qu'à la fin

Selon la situation :

SituationChoix
Une ou deux conditions simplesIF
Plusieurs cas possibles, lisibilitéCASE
Nombre de répétitions inconnu, tester avantWHILE
Il faut exécuter au moins une foisREPEAT
Sortie au milieu de la boucleLOOP + LEAVE

6. Méthodologie simple

  1. Écrire le problème en français : « si..., alors... sinon... » ou « tant que... ».
  2. Identifier les variables nécessaires et les déclarer avec DECLARE (au début du bloc).
  3. Choisir la structure (tableau ci-dessus).
  4. Écrire la condition avec les opérateurs : =, <>, <, >=, AND, OR, IS NULL.
  5. Pour une boucle : vérifier que la condition finit par devenir fausse (ou que LEAVE est atteint).
  6. Tester avec CALL sur plusieurs cas, y compris les cas limites (valeur NULL, valeur de départ déjà au-delà de la condition).
À retenir : IF ... END IF; · CASE ... END CASE; · WHILE ... DO ... END WHILE; · REPEAT ... UNTIL ... END REPEAT; · LOOP ... END LOOP;

7. Travaux pratiques (TP)

Base utilisée : Glogiciels (developpeur, projet, logiciel, realisation). Essayez chaque question avant d'ouvrir la correction.

TP 1 : fonction TesterTable

Créer une fonction TesterTable qui renvoie 0 si la table developpeur contient moins de 10 lignes et 1 sinon.

Voir la correction 
DELIMITER //
CREATE FUNCTION TesterTable() RETURNS INT
READS SQL DATA
BEGIN
    DECLARE v_nb INT;

    SELECT COUNT(*) INTO v_nb FROM developpeur;

    IF v_nb < 10 THEN
        RETURN 0;
    ELSE
        RETURN 1;
    END IF;
END //
DELIMITER ;

SELECT TesterTable();
READS SQL DATA est nécessaire car la fonction lit une table. Sans cette clause, MySQL peut refuser la création (erreur 1418) lorsque le journal binaire est activé.

TP 2 : procédure AjouterDeveloppeur

Créer une procédure AjouterDeveloppeur qui prend en paramètres les informations d'un développeur, puis tente de l'insérer dans la table developpeur. La procédure appelle la fonction du TP 1 pour vérifier que la table n'est pas pleine : si elle contient moins de 10 développeurs, on insère le nouveau développeur ; sinon, on affiche le message 'Table pleine'. Tester la procédure.

Voir la correction 
DELIMITER //
CREATE PROCEDURE AjouterDeveloppeur(
    IN p_numdev   INT,
    IN p_nomdev   VARCHAR(50),
    IN p_adrdev   VARCHAR(100),
    IN p_emaildev VARCHAR(100),
    IN p_teldev   VARCHAR(20)
)
BEGIN
    IF TesterTable() = 0 THEN
        INSERT INTO developpeur (numdev, nomdev, adrdev, emaildev, teldev)
        VALUES (p_numdev, p_nomdev, p_adrdev, p_emaildev, p_teldev);
        SELECT 'Développeur ajouté' AS message;
    ELSE
        SELECT 'Table pleine' AS message;
    END IF;
END //

CALL AjouterDeveloppeur(101, 'Alami', 'Casablanca', 'alami@mail.ma', '0600000001');
SELECT COUNT(*) FROM developpeur;

TP 3 : procédure AjouterLogiciel

Créer une procédure AjouterLogiciel qui permet d'insérer les informations d'un logiciel donné. Le logiciel doit appartenir à un projet non terminé (datefin vide ou postérieure à aujourd'hui), sinon afficher le message 'Le projet est terminé !'. Tester la procédure.

Voir la correction 
DELIMITER //
CREATE PROCEDURE AjouterLogiciel(
    IN p_codlog  INT,
    IN p_nomlog  VARCHAR(50),
    IN p_prixlog DECIMAL(10,2),
    IN p_numproj INT
)
BEGIN
    DECLARE v_nb  INT;
    DECLARE v_fin DATE;

    SELECT COUNT(*) INTO v_nb FROM projet WHERE numproj = p_numproj;

    IF v_nb = 0 THEN
        SELECT 'Projet introuvable !' AS message;
    ELSE
        SELECT datefin INTO v_fin FROM projet WHERE numproj = p_numproj;

        IF v_fin IS NOT NULL AND v_fin < CURDATE() THEN
            SELECT 'Le projet est terminé !' AS message;
        ELSE
            INSERT INTO logiciel (codlog, nomlog, prixlog, numproj)
            VALUES (p_codlog, p_nomlog, p_prixlog, p_numproj);
            SELECT 'Logiciel ajouté' AS message;
        END IF;
    END IF;
END //
DELIMITER ;

CALL AjouterLogiciel(901, 'GestStock', 1200, 1);   -- projet en cours : ajouté
CALL AjouterLogiciel(902, 'OldApp',     300, 2);   -- projet terminé : message
CALL AjouterLogiciel(903, 'Test',       100, 999); -- projet inexistant : message
Choisissez des numproj qui correspondent à vos données (un projet en cours et un projet terminé). Le test « projet introuvable » évite qu'une valeur NULL passe pour un projet non terminé.

TP 4 : appréciation selon le nombre de projets

Pour chaque développeur, afficher selon le nombre total de projets réalisés :

  • 'Pas de projet' si total = 0
  • 'Nombre de projets inférieur à 3' si total < 3
  • 'Trois projets ou plus' si total >= 3
Voir la correction 
SELECT d.numdev, d.nomdev,
       COUNT(r.numproj) AS total,
       CASE
           WHEN COUNT(r.numproj) = 0 THEN 'Pas de projet'
           WHEN COUNT(r.numproj) < 3 THEN 'Nombre de projets inférieur à 3'
           ELSE 'Trois projets ou plus'
       END AS appreciation
FROM developpeur d
LEFT JOIN realisation r ON r.numdev = d.numdev
GROUP BY d.numdev, d.nomdev;
Le LEFT JOIN garde les développeurs sans projet (total = 0). Avec un JOIN simple, ils disparaîtraient du résultat.
