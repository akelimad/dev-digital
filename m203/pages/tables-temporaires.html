Les tables temporaires en MySQL

Un support de révision pour les stagiaires : ce qu'est une table temporaire, comment elle se comporte pendant une session, et les pièges classiques à éviter en TP comme en entretien technique.

01 Définition

Une table temporaire est une table créée avec le mot-clé TEMPORARY. Elle se comporte comme une table normale (on peut y insérer, la mettre à jour, la joindre, l'indexer), mais elle n'existe que pour la durée de la connexion qui l'a créée.

session_A
CREATE TEMPORARY TABLE resultats_partiels (
    id INT PRIMARY KEY,
    total DECIMAL(10,2)
);

INSERT INTO resultats_partiels VALUES (1, 450.00);
SELECT * FROM resultats_partiels;

Elle est visible uniquement dans la session qui l'a créée — aucune autre connexion, même avec le même compte MySQL, ne peut la voir ni y accéder.

02 Portée et cycle de vie

Trois règles à retenir sur son cycle de vie :

Isolée par connexion

Deux sessions peuvent créer une table temporaire portant le même nom sans jamais entrer en conflit.

Supprimée automatiquement

Dès que la connexion se ferme, MySQL détruit la table — pas besoin de nettoyage manuel.

Suppression explicite possible

DROP TEMPORARY TABLE nom; permet de la supprimer avant la fin de session.

Masque une table permanente

Si une table permanente porte déjà ce nom, la version temporaire prend le dessus pendant la session.

Démonstration — isolation entre deux sessions

Deux stagiaires ouvrent chacun leur propre connexion MySQL. L'un crée une table temporaire ; l'autre tente de la lire.

04 Cas d'usage typiques

En pratique, on utilise une table temporaire pour découper un problème complexe en étapes plus simples :

Résultats intermédiaires

Stocker le résultat d'une sous-requête coûteuse pour la réutiliser plusieurs fois sans la recalculer.

Simplifier une procédure stockée

Décomposer un traitement en plusieurs étapes lisibles au lieu d'une seule requête imbriquée illisible.

Agrégations en plusieurs passes

Calculer un premier regroupement, puis effectuer un second traitement sur ce résultat.

Import / transformation de données

Charger des données brutes, les nettoyer, puis alimenter la table définitive avec des données validées.

05 Pièges et limites à connaître

Invisible dans SHOW TABLES Une table temporaire n'apparaît pas avec SHOW TABLES. Un stagiaire qui cherche « pourquoi ma table n'existe pas » alors qu'il vient de la créer confond souvent ce point.
Stockage et mémoire Une table temporaire trop volumineuse peut basculer du moteur mémoire vers le disque, selon tmp_table_size et max_heap_table_size. Elle n'est pas gratuite en performance.
Une seule référence par requête (historique) Sur des versions plus anciennes de MySQL, on ne pouvait pas référencer une même table temporaire deux fois dans la même requête (par exemple une auto-jointure). Bon réflexe : vérifier la version utilisée en TP avant d'écrire ce type de requête.
Portée oubliée en connexion poolée Avec un pool de connexions (applications web, ORM), la « session » peut changer d'une requête à l'autre : une table temporaire créée sur une connexion peut disparaître avant la requête suivante si le pool réattribue une autre connexion.

06 Ne pas confondre avec les tables temporaires internes

MySQL crée lui-même, en interne, des tables temporaires invisibles pour exécuter certaines requêtes complexes — sans aucun lien avec CREATE TEMPORARY TABLE.

moteur MySQL (interne)
-- Ces opérations peuvent forcer la création
-- d'une table temporaire interne :
SELECT categorie, COUNT(*)
FROM produits
GROUP BY categorie
ORDER BY COUNT(*) DESC;

SELECT DISTINCT ville FROM clients;

(SELECT id FROM a) UNION (SELECT id FROM b);

On peut observer ce comportement avec EXPLAIN, qui affiche Using temporary dans la colonne Extra. Le stagiaire n'écrit jamais ce type de table lui-même : c'est l'optimiseur MySQL qui décide.

07 Ce qu'il faut absolument retenir

  • ✓ Une table temporaire se crée avec CREATE TEMPORARY TABLE et se comporte comme une table normale.
  • ✓ Elle n'est visible que dans la session qui l'a créée, jamais dans SHOW TABLES.
  • ✓ Elle disparaît automatiquement à la fermeture de la connexion, ou avec DROP TEMPORARY TABLE.
  • ✓ Elle peut porter le même nom qu'une table permanente : elle la masque pendant la session.
  • ✓ Elle sert à découper un traitement complexe en étapes intermédiaires lisibles.
  • ✓ Elle est distincte des tables temporaires internes que MySQL crée seul pour GROUP BY, DISTINCT ou UNION.
