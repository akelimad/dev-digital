Les vues : une fenêtre sur les données

Comprendre leur rôle avec la base Développeurs / Projets / Logiciels, puis suivre leur cycle de vie.

1 — L'idée

Une vue, c'est quoi ?

Une vue est une représentation virtuelle de données provenant d'une ou plusieurs tables. On peut l'imaginer comme un miroir : elle montre les données de la table source, mais elle ne crée pas une deuxième copie de ces données.

À retenir : une vue ne contient pas une copie indépendante des lignes. Elle présente le résultat de sa définition.
2 — Notre base

La base de données utilisée

developpeur (numdev, nomdev, adrdev, emaildev, teldev)
projet      (numproj, titreproj, datedeb, datefin)
logiciel    (codlog, nomlog, prixlog, #numproj)
realisation (#numproj, #numdev)

On va utiliser surtout developpeur, puis une vue basée sur plusieurs tables.

3 — Cas simple

Créer une vue avec une seule table

On veut présenter les développeurs à travers une vue.

CREATE VIEW vue_developpeurs AS
SELECT *
FROM developpeur;

Lire la vue

SELECT * FROM vue_developpeurs;
SELECT

La vue affiche les données de developpeur.

INSERT

Si la vue est modifiable, l'insertion passe dans la table source.

UPDATE / DELETE

Les modifications passent également sur la table source.

DELETE FROM vue_developpeurs
WHERE numdev = 10;

Attention : ce DELETE ne supprime pas la vue. Il supprime la ligne correspondante de la table developpeur, si la vue est modifiable.

4 — Cas avec JOIN

Une vue qui rassemble plusieurs tables

On veut voir directement quel développeur travaille sur quel projet.

CREATE VIEW vue_developpeurs_projets AS
SELECT d.nomdev, p.titreproj
FROM developpeur d
JOIN realisation r
  ON d.numdev = r.numdev
JOIN projet p
  ON r.numproj = p.numproj;
SELECT * FROM vue_developpeurs_projets;
Pourquoi cette vue n'est pas comme la précédente ?
Le résultat provient de plusieurs tables reliées par des JOIN. Ce type de vue est généralement non modifiable pour les opérations comme INSERT/UPDATE/DELETE, selon sa définition et les règles de MySQL.
5 — Pourquoi utiliser une vue ?

Alors pourquoi ne pas faire directement le SELECT ?

Pour une requête ponctuelle, le stagiaire a raison : un SELECT direct suffit.

L'intérêt apparaît lorsqu'une requête est réutilisée, lorsqu'elle est complexe, ou lorsqu'on veut donner accès à une présentation limitée des données.

Supprimer la vue

Important : DROP VIEW supprime la vue, pas la table developpeur. Les données de la table source restent présentes.
7 — Résumé à retenir

Une phrase pour l'examen

Une vue est une représentation virtuelle de données basée sur une requête SELECT. Elle peut être consultée comme une table et, lorsqu'elle est modifiable, certaines opérations INSERT, UPDATE ou DELETE se répercutent sur les tables sources.
