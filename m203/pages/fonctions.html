🧮 Les Fonctions Stockées

Comprendre les fonctions simplement : paramètres, RETURN et appel dans un SELECT

1. Définition

Une fonction stockée est un sous-programme enregistré dans la base de données avec un nom. Elle reçoit des paramètres et renvoie une seule valeur grâce à RETURN. On l'appelle comme une fonction native (UPPER(), SUM()...) : directement dans un SELECT, un WHERE, etc.

💡 Image simple : c'est comme une formule de calculatrice qu'on s'est fabriquée. On donne des nombres, elle rend un résultat, et on peut l'utiliser partout où une valeur est attendue.

Ce qu'elle peut contenir

  • Des variables (DECLARE) et des requêtes SELECT ... INTO.
  • Des instructions conditionnelles : IF, CASE.
  • Des boucles.
  • L'appel d'une autre fonction pour découper le code en modules.

2. Pourquoi les utiliser ? (Utilité et avantages)

👉 Quand l'utiliser ? Dès qu'un calcul ou une règle est répété dans plusieurs requêtes et qu'on veut en tirer une seule valeur.
♻️ Réutilisable
On écrit le calcul une fois et on l'appelle dans toutes les requêtes qui en ont besoin.
👁️ Requêtes plus lisibles
prix_ttc(prixlog, 20) est plus clair qu'une formule recopiée partout.
🛠️ Facile à maintenir
Si la règle change (ex : taux de TVA), on modifie un seul endroit. Les résultats restent cohérents.

3. Cas d'utilisation

👨‍💻 Développeurs
Retrouver le nom d'un développeur à partir de son numéro.
📁 Projets
Compter les logiciels ou les développeurs d'un projet.
💿 Logiciels
Calculer un prix TTC ou classer un prix (économique, standard, premium).
📊 Rapports
Obtenir le total des prix des logiciels d'un projet.

4. Notre base de données

Tous les exemples utilisent la même base : des développeurs qui réalisent des projets, et chaque projet a des logiciels.

👨‍💻 developpeur
numdev (PK), nomdev, adrdev, emaildev, teldev
📁 projet
numproj (PK), titreproj, datedeb, datefin
💿 logiciel
codlog (PK), nomlog, prixlog, numproj (FK → projet)
🔗 realisation
numproj + numdev (PK composée, FK vers projet et developpeur)
💡 Relations : un projet contient plusieurs logiciels (1,N) · un développeur peut travailler sur plusieurs projets et un projet a plusieurs développeurs (N,N via realisation).

5. Syntaxe (MySQL)

-- Changer le délimiteur pour pouvoir écrire ; dans la fonction
DELIMITER //

CREATE FUNCTION nom_fonction(param1 TYPE, param2 TYPE)
RETURNS TYPE_RETOUR
READS SQL DATA          -- ou DETERMINISTIC (voir ci-dessous)
BEGIN
    DECLARE v_resultat TYPE;
    -- instructions SQL
    RETURN v_resultat;
END //

DELIMITER ;

-- Appel : dans un SELECT (et non avec CALL)
SELECT nom_fonction(...);

-- Suppression
DROP FUNCTION nom_fonction;
CaractéristiqueQuand l'utiliser ?
DETERMINISTICMêmes paramètres → toujours le même résultat, sans lire de table (ex : calcul de TVA).
READS SQL DATALa fonction lit des tables (SELECT) sans les modifier.
MODIFIES SQL DATALa fonction modifie des données (déconseillé dans une fonction).
NO SQLAucune instruction SQL dans la fonction.
⚠️ Erreur fréquente : si on oublie de déclarer DETERMINISTIC, NO SQL ou READS SQL DATA, MySQL peut refuser la création : ERROR 1418 : This function has none of DETERMINISTIC, NO SQL, or READS SQL DATA in its declaration and binary logging is enabled. Il suffit d'ajouter la bonne caractéristique.

6. Méthodologie simple (5 étapes)

  1. Définir le besoin : quelle valeur la fonction doit-elle calculer ? (ex : le prix TTC d'un logiciel)
  2. Choisir les paramètres et le type de retour : qu'est-ce qui entre ? Quel type de valeur sort (RETURNS) ?
  3. Écrire le corps dans BEGIN ... END avec un RETURN à la fin.
  4. Créer la fonction (exécuter le CREATE FUNCTION).
  5. Appeler et tester avec SELECT.

7. Un exemple très simple

Sans paramètre : renvoyer le nombre de développeurs.

DELIMITER //
CREATE FUNCTION nb_developpeurs()
RETURNS INT
READS SQL DATA
BEGIN
    DECLARE v_nb INT;
    SELECT COUNT(*) INTO v_nb FROM developpeur;
    RETURN v_nb;
END //
DELIMITER ;

SELECT nb_developpeurs();

8. Les paramètres d'une fonction

👉 Dans une fonction, tous les paramètres sont des entrées (IN implicite). On n'écrit jamais IN, OUT ni INOUT : le résultat sort par RETURN.

IN Exemple 1 : un paramètre

Compter les logiciels d'un projet donné.

DELIMITER //
CREATE FUNCTION nb_logiciels(p_numproj INT)
RETURNS INT
READS SQL DATA
BEGIN
    DECLARE v_nb INT;
    SELECT COUNT(*) INTO v_nb
    FROM logiciel
    WHERE numproj = p_numproj;
    RETURN v_nb;
END //
DELIMITER ;

SELECT nb_logiciels(1);
SELECT titreproj, nb_logiciels(numproj) AS nb FROM projet;   -- dans une requête

IN Exemple 2 : plusieurs paramètres (calcul)

Calculer un prix TTC à partir d'un prix HT et d'un taux de TVA.

DELIMITER //
CREATE FUNCTION prix_ttc(p_prix DOUBLE, p_tva DOUBLE)
RETURNS DOUBLE
DETERMINISTIC
BEGIN
    RETURN p_prix + (p_prix * p_tva / 100);
END //
DELIMITER ;

SELECT prix_ttc(1000, 20);                          -- 1200
SELECT nomlog, prixlog, prix_ttc(prixlog, 20) AS ttc
FROM logiciel;

IN Exemple 3 : avec une condition (IF)

Classer un logiciel selon son prix.

DELIMITER //
CREATE FUNCTION categorie_prix(p_prix DOUBLE)
RETURNS VARCHAR(20)
DETERMINISTIC
BEGIN
    DECLARE v_cat VARCHAR(20);
    IF p_prix < 1000 THEN
        SET v_cat = 'Économique';
    ELSEIF p_prix <= 5000 THEN
        SET v_cat = 'Standard';
    ELSE
        SET v_cat = 'Premium';
    END IF;
    RETURN v_cat;
END //
DELIMITER ;

SELECT nomlog, prixlog, categorie_prix(prixlog) FROM logiciel;
⚠️ Erreur fréquente : les paramètres et variables ne doivent pas porter le même nom qu'une colonne. C'est pourquoi on utilise des préfixes : p_ pour les paramètres, v_ pour les variables.

9. Que retourne une fonction ? Une seule valeur

Une fonction renvoie une seule valeur (un nombre, un texte, une date...), dont le type est donné par RETURNS. Elle ne peut pas renvoyer une liste de lignes.

-- ❌ Faux : un SELECT qui renvoie des lignes est interdit dans une fonction
CREATE FUNCTION liste_devs() RETURNS INT READS SQL DATA
BEGIN
    SELECT * FROM developpeur;
    RETURN 1;
END
-- Erreur MySQL : Not allowed to return a result set from a function

-- ❌ Faux : une fonction ne s'appelle pas avec CALL
CALL nb_logiciels(1);

-- ✅ Correct : on l'appelle dans un SELECT ou une condition
SELECT nb_logiciels(1);
SELECT nomlog FROM logiciel WHERE prix_ttc(prixlog, 20) > 6000;
💡 Avantage majeur : comme elle renvoie une valeur, une fonction s'utilise partout où une valeur est attendue : dans la liste du SELECT, dans un WHERE, un ORDER BY, ou même dans une autre fonction.

Fonction ou procédure ?

FonctionProcédure
AppelSELECT ma_fonction(...)CALL ma_procedure(...)
ParamètresIN seulementIN, OUT, INOUT
RésultatUne seule valeur (RETURN)Zéro, une ou plusieurs valeurs (OUT) et/ou des lignes (SELECT)
Dans un SELECT / WHERE✅ Oui❌ Non
Usage typiqueCalculer une valeurExécuter un traitement (ajouts, modifications, rapports)

10. À retenir

  • Une fonction = un sous-programme SQL enregistré qui renvoie une seule valeur avec RETURN.
  • On déclare le type du résultat avec RETURNS et une caractéristique (DETERMINISTIC ou READS SQL DATA).
  • Les paramètres sont toujours des entrées : pas de IN, OUT ni INOUT.
  • On l'appelle avec SELECT (ou dans une expression), jamais avec CALL.
  • Elle ne peut pas renvoyer une liste de lignes : pour cela, on utilise une procédure stockée.
  • Avantages : réutilisation, lisibilité, cohérence, maintenance.

RETURNS DOUBLE
READS SQL DATA
